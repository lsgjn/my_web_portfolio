# 05. 구조(틀 / 내용물 / 함수)와 로컬 관리자

## 1. 세 갈래 구조
| 구분 | 폴더 | 역할 |
|---|---|---|
| 틀 | `src/frames/` | 화면의 뼈대와 속성(props). 안에 들어갈 내용물은 `children`으로 받는다 |
| 내용물 | `src/components/<종류>/` | 틀 안에 들어가는 조각. 종류별 폴더로 분리 |
| 함수 | `src/functions/` | 사이트를 구동하는 로직(콘텐츠 로딩, 언어, 관리자 API 호출) |

### 틀과 속성
- `SiteFrame` : 헤더 + 본문 + 푸터. 라우트의 `:lang`으로 언어 결정
- `PageFrame` : `title`, `description`, `heading`, `width("default"|"narrow")`
- `SectionFrame` : `title`, `to`, `linkLabel`, `spacing`
- `AdminFrame` : 관리자 전용 상단 바 + 작업 영역

### 내용물 폴더
`ui`(Button, TagChip, SectionTitle, EmptyState, MediaViewer) · `nav`(Header, Footer, LangSwitch) · `home` · `project` · `blog` · `about` · `admin`(DropZone, ItemList, ItemEditor, MediaList)

### 함수 파일
`content.js`(프로젝트/글 수집) · `data.js`(프로필/스킬/이력) · `i18n.js`(언어 훅, UI 문구) · `admin-api.js`(관리자 API 호출) · `admin-helpers.js`(폼 ↔ frontmatter 변환 등)

## 2. 로컬 전용 관리자
- 실행: `npm run dev` → 브라우저에서 `http://localhost:5173/admin`
- 블로그 글 / 프로젝트 목록, 새로 쓰기, 수정, 삭제
- 드래그 앤 드롭: 본문 입력창에 이미지·영상을 끌어다 놓으면 `public/media/<slug>/`에 저장되고 마크다운이 커서 위치에 삽입된다. 프로젝트의 미디어 영역에 놓으면 갤러리에 추가되고, 첫 이미지가 썸네일이 된다
- 저장하면 `src/content/{projects,posts}/{ko,en}/<slug>.md`가 만들어지고 개발 서버가 즉시 반영한다
- 배포: 변경된 파일을 git commit / push → 호스팅이 자동 빌드

## 3. 읽는 사람은 수정할 수 없다 (보안 구조)
1. **관리자 코드가 배포본에 없다.** 관리자 화면은 `import.meta.env.DEV`일 때만 라우트에 연결되고, 서버 API는 Vite 플러그인(`apply: "serve"`)이라 `npm run build` 결과에 포함되지 않는다. 배포 사이트의 `/admin`은 404
2. **수정 수단 자체가 없다.** 배포 사이트는 정적 파일이라 서버도 쓰기 API도 없다. 읽는 사람이 볼 수 있는 것은 내가 `content/`·`public/media/`에 넣고 push한 것뿐이다
3. 개발 서버 API 방어: localhost Host만 허용, 다른 사이트 Origin 거부, 커스텀 헤더 필수, slug/언어/확장자 화이트리스트, 경로 탈출 차단, 업로드 50MB 제한
4. 마크다운의 원본 HTML은 렌더링하지 않는다(XSS 방지)
5. 외부 링크는 `rel="noopener noreferrer"`

주의: 개발 서버를 `--host` 옵션으로 열어 외부에 공개하지 말 것. 초안은 `draft: true`로 두면 배포본에서 제외된다.

## 4. 알려진 한계
- 삭제 시 첨부 파일(`public/media/<slug>/`)은 남는다 (직접 정리)
- 글/프로젝트의 한/영 버전은 각각 따로 작성한다
- 프로필·이력·기술 스택은 관리자의 "프로필 · 이력" 탭에서 편집한다 (`src/content/data/*.json`에 저장). 이력서 PDF는 끌어다 놓으면 `public/media/resume/`에 저장되고 경로가 자동 입력된다
- 프로필 항목 중 편집기에 없는 키는 저장해도 유지된다
