# 01. 기획

## 1. 목적과 대상
- 목적: 취업(게임 클라이언트 개발자) + 프리랜서/1인 개발(풀스택에 가까움) 겸용
- 대상: 게임 회사 채용담당자·개발자 / 외주 클라이언트
- 포지셔닝: "게임 클라이언트를 만들 수 있고, 서버·웹까지 혼자 완성하는 개발자"
- 현재 상태: 신입/취준생, 프로젝트 0개, 대학교 AI소프트웨어학과 (재적 상태 확인 필요 → 아래 미결정 항목)

## 2. 사이트 구조

### 언어
- 한국어 / 영어 페이지를 **별도 라우트로 분리** (`/ko`, `/en`), 상단에 언어 전환 버튼
- 콘텐츠도 언어별로 분리 관리 (프로젝트 파일, 글 모두 ko/en 별도 작성, 번역이 없으면 해당 언어 목록에서 제외)

### 페이지
| 경로 | 내용 |
|---|---|
| Home | Hero(한 줄 소개 + CTA 2개), About 요약, 대표 프로젝트, Skills, 최근 글, 함께 일하기 |
| About | 자기소개(직접 작성), 학력·활동 타임라인 |
| Projects / Projects/:slug | 프로젝트 목록(기술·종류 필터) / 상세 |
| Blog / Blog/:slug | 일상적인 개발 기록 (태그, 날짜순) |
| Contact | 이메일, GitHub, 이력서 PDF, 문의 |

### CTA
- [이력서 보기 / 지원] (채용용), [프로젝트 문의] (프리랜서용)

## 3. 프로젝트 소개 방식 (게임 특화)
- 상세 구성: 개요 → 장르/플랫폼 → 맡은 역할 → 사용 기술(엔진, 언어) → 문제와 해결 → 결과/배운 점 → 링크
- 게임은 **플레이 영상/GIF, 스크린샷, 가능하면 WebGL 빌드 또는 다운로드 링크**를 반드시 포함
- 풀스택/서버 프로젝트(멀티플레이, 랭킹 서버, 툴 등)는 "1인 개발" 태그로 구분
- 프로젝트 0개 대응: 이 포트폴리오 사이트를 1번 프로젝트로 등록, 이후 게임 데모 1~2개 + 풀스택 1개를 목표로 제작 (대표작 3개 이상)

## 4. 콘텐츠 자동화 요구사항
- 콘텐츠는 `content/` 폴더에서 별도 관리, 파일을 추가하면 목록/상세가 자동 생성
  - `content/projects/{ko,en}/*.md` (frontmatter: 제목, 요약, 기간, 역할, 기술[], 썸네일, 링크, 대표작 여부, 순서)
  - `content/posts/{ko,en}/*.md` (frontmatter: 제목, 날짜, 태그, 요약)
  - `content/profile`, `content/timeline`, `content/skills` 등은 데이터 파일로 분리
- 코드 수정 없이 내용만 추가/수정 가능해야 함
- 구현 방법은 3단계(기술스택)에서 확정

## 5. 경력/활동
- 실무 경력 없음 → 학력, 수업/팀 프로젝트, 공모전·해커톤, 자격증, 독학 기록을 타임라인으로 구성
- 학력 표기 방식은 확정 후 작성

## 6. 블로그
- 형식: 일상적인 개발 기록 (짧은 글 위주, 부담 없는 작성 흐름)
- 기능: 태그, 날짜 정렬, 코드 하이라이팅, 이미지/영상 삽입
- 프로젝트와 글을 연결 (프로젝트 상세에서 관련 개발 기록 링크)

## 7. 미결정 / 확인 필요
1. 학력 상태: "제적"이 의도한 표현인지(제적=학적 상실) 재적(재학)의 오타인지. 제적이라면 표기 방식·강조점이 달라짐
2. 주력 엔진/언어: Unity(C#) 또는 Unreal(C++) 등
3. 풀스택 쪽 주력 스택: 서버 언어/프레임워크
4. 영어 페이지 작성 범위: 전체 vs 핵심 페이지만
5. 첫 프로젝트 후보 및 제작 일정
