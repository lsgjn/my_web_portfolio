# 04. 섹션 구성

각 페이지를 섹션 단위로 쪼개 "무엇을 보여주고, 데이터를 어디서 가져오고, 어떤 컴포넌트로 만드는지"를 정리한다.

## 1. 라우트
| 경로 | 페이지 |
|---|---|
| `/` | 브라우저 언어 기준으로 `/ko` 또는 `/en`으로 이동 |
| `/:lang` | Home |
| `/:lang/projects` | 프로젝트 목록 |
| `/:lang/projects/:slug` | 프로젝트 상세 |
| `/:lang/blog` | 블로그 목록 |
| `/:lang/blog/:slug` | 블로그 상세 |
| `/:lang/about` | About |
| `/:lang/contact` | Contact |
| `*` | 404 |

`lang`은 `ko | en`만 허용. 그 외 값은 404. 반대 언어에 같은 slug 번역이 있으면 언어 전환 시 해당 페이지로, 없으면 해당 언어의 목록으로 이동.

## 2. 공통 레이아웃
- **Header**: 이름 로고, 네비(Projects, Blog, About, Contact), 언어 전환, 모바일 햄버거. 스크롤 시 상단 고정
- **Footer**: 이메일, GitHub, 저작권
- 모든 페이지 공통으로 `<title>`, 설명, OG 이미지를 설정

## 3. Home 섹션 (위에서 아래 순서)
| # | 섹션 | 내용 | 데이터 |
|---|---|---|---|
| 1 | Hero | 직군 라벨, 헤드라인, 한 줄 소개, CTA 2개(이력서, 문의) | `data/profile.{lang}.json` |
| 2 | Featured Projects | `featured: true` 프로젝트 최대 3개 카드, "전체 보기" 링크 | `content/projects/{lang}` |
| 3 | Skills | 카테고리별(Game / Backend / Web / Tools) 기술 칩 | `data/skills.json` |
| 4 | Latest Posts | 최신 글 3개, "전체 보기" 링크 | `content/posts/{lang}` |
| 5 | Work with me | 가능한 작업 범위, 진행 방식, 문의 버튼 | `data/profile.{lang}.json` |

프로젝트나 글이 0개일 때: 해당 섹션에 "준비 중" 빈 상태를 보여주고, 글/프로젝트가 있으면 자동으로 대체.

## 4. Projects
- **목록**: 필터 칩(기술/종류), 카드 그리드. 카드 = 썸네일, 제목, 한 줄 요약, 기술 태그, 기간
- **상세 섹션**
  1. 헤더: 제목, 요약, 링크 버튼(GitHub, 플레이/배포)
  2. 미디어: 영상/GIF/스크린샷 갤러리 (WebGL은 iframe 또는 외부 링크)
  3. 메타 사이드: 기간, 역할, 인원(1인/팀), 기술, 플랫폼
  4. 본문(마크다운): 개요 → 맡은 역할 → 문제와 해결 → 결과와 배운 점
  5. 관련 글: 같은 `project` 태그를 가진 블로그 글
  6. 이전/다음 프로젝트
- frontmatter: `title, summary, period, role, team, stack[], platform, thumbnail, media[], links{github, demo}, featured, order, tags[]`

## 5. Blog
- **목록**: 날짜 역순, 태그 필터, 항목 = 제목, 날짜, 태그, 요약
- **상세**: 단일 컬럼(최대 720px), 제목/날짜/태그, 본문, 코드 하이라이팅, 이전/다음 글
- frontmatter: `title, date, tags[], summary, project(선택), draft(선택)`
- `draft: true`인 글은 프로덕션 빌드에서 제외

## 6. About
1. 자기소개: 사진(선택), 본문 3~4문단 (직접 작성)
2. 강점/일하는 방식 3가지
3. 타임라인: 학력, 활동, 수상, 자격증 (`data/timeline.{lang}.json`, 항목 = 기간, 제목, 설명, 종류)
4. Skills 상세(Home보다 자세히, 선택)

## 7. Contact
이메일(복사 버튼), GitHub, 이력서 PDF 다운로드, 가능한 작업 안내. 폼은 1차에서 제외하고 메일 링크로 대체 (스팸/백엔드 부담 회피).

## 8. 컴포넌트 ↔ 폴더 구조
```
src/
  main.jsx, App.jsx, router.jsx
  i18n/            ui 문구 사전 (ko.js, en.js), useLang 훅
  content/         마크다운 + data (04 문서 3~4절 참고)
  lib/             content.js (glob 수집, frontmatter 파싱, 정렬/필터)
  components/
    layout/        Header, Footer, LangSwitch, Layout
    ui/            Button, TagChip, SectionTitle, EmptyState, MediaViewer
    project/       ProjectCard, ProjectGrid, FilterBar
    blog/          PostItem, PostList, Markdown
    home/          Hero, FeaturedProjects, Skills, LatestPosts, WorkWithMe
    about/         Timeline
  pages/           Home, Projects, ProjectDetail, Blog, PostDetail, About, Contact, NotFound
```

## 9. 개발 진행 순서 (5단계 세부 계획)
1. 패키지 설치, 폴더 구조, Tailwind `@theme` 토큰, 폰트
2. Layout(Header/Footer), 라우터, 언어 전환(i18n)
3. 콘텐츠 로더(`lib/content.js`) + 샘플 마크다운 몇 개
4. Projects 목록/상세, Blog 목록/상세
5. Home, About, Contact 섹션
6. SEO, 접근성, 반응형 점검, 404
7. 배포 (Cloudflare Pages 또는 Vercel)

## 10. 미결정
1. 언어 자동 판별 방식 (브라우저 언어 vs 항상 `/ko`)
2. 프로젝트 카테고리 구분(게임/풀스택/툴) 필터 항목
3. About 사진 사용 여부
4. 문의 방식을 메일 링크로 할지, 이후 폼을 추가할지
